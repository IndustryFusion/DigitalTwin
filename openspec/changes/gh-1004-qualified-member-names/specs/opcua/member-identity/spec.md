## Purpose
Defines which member that an OPC UA type or an instance declaration declares a child of an instance is, as the instances and shapes generated by the OPC UA tools see it.

## ADDED Requirements

### Requirement: A fixed-name member is identified by namespace and name
A child of an instance SHALL be the member that its parent's type, or the declaration of its parent, declares with a fixed name only when the child's browse name has the same namespace and the same name as the declared member. This SHALL hold for objects and variables, and for the members of a type and those a declaration adds. A namespace URI spelled with or without its trailing separator SHALL be the same namespace.

#### Scenario: Members of another namespace are not the type's members
- **GIVEN** an `AlphaType` that declares the mandatory members `1:Level` and `1:Link`
- **WHEN** an `AlphaType` instance has the children `0:Level` and `0:Link`
- **THEN** validation reports the missing `hasLevel` and the missing `hasLink` of the namespace of `AlphaType` on the instance

#### Scenario: A member a declaration adds, in another namespace
- **GIVEN** the declaration of `1:Link` adds the mandatory variable `1:Status`
- **WHEN** an `AlphaType` instance has `1:Level` and `1:Link`, and its `Link` has the child `0:Status`
- **THEN** validation reports a violation on the instance for its relationship to `Link` whose cause is the missing `hasStatus`, and nothing for `Level` or `Link` themselves

### Requirement: A child that is no member keeps its own attribute
A child that is no fixed-name member of its parent's type or declaration, and no instance of a placeholder, SHALL be kept as an attribute named from its own browse name's namespace and name.

#### Scenario: The child of another namespace appears under its own name
- **GIVEN** the `AlphaType` of the first scenario
- **WHEN** the instances are generated for an instance with the children `0:Level` and `0:Link`
- **THEN** the instance has the attributes `hasLevel` and `hasLink` of namespace 0, and none of the namespace of `AlphaType`

### Requirement: Placeholder instances may be in any namespace
A child SHALL count as an instance of a placeholder member whatever the namespace of its browse name. Its membership SHALL be decided by its name and its type as for a placeholder in its own namespace.

#### Scenario: A placeholder instance of namespace 0
- **GIVEN** an `AlphaType` that declares the optional placeholder `1:<Part>` of type `PartType`
- **WHEN** an instance has the child `0:PartA` of type `PartType`
- **THEN** `PartA` is an instance of `<Part>`, and no violation is reported for it

### Requirement: Data type and value rank come from the member of the same QualifiedName
A child variable's data type and value rank SHALL be taken from the declared variable of its parent's type only when the child is that member by namespace and name.

#### Scenario: A variable of another namespace keeps its own value rank
- **GIVEN** an `AlphaType` that declares the variable `1:Level` with value rank 1 (an array)
- **WHEN** an instance has a variable `0:Level` without a value, of a scalar variable type
- **THEN** its generated value is a scalar, while a `1:Level` without a value is generated as an array

### Requirement: Member identity is documented
The documentation of the OPC UA tools SHALL describe that members with a fixed name are identified by namespace and name, that instances of placeholders may be in any namespace, and what happens to a child that is no member.

#### Scenario: A reader learns why a child of another namespace is reported as missing
- **WHEN** a reader looks up member identity in the documentation of the OPC UA tools
- **THEN** it explains the namespace-and-name rule with an example, the exception for placeholders, and where the violation is reported
